# Markdown AST Rendering Implementation Guide

## Overview

This document outlines the complete implementation of Markdown AST rendering for the monofolio-v2 frontend. The system converts the JSON Abstract Syntax Tree (AST) generated by the backend's markdown parser into interactive Leptos components.

## Architecture

### Current State

**Backend (Rust - Actix):**
- Parses markdown files using `pulldown-cmark`
- Builds AST as `Vec<MarkdownNode>`
- Stores in `MarkdownContent` container
- Serializes to JSON via `/api/v1/page/{handle}` endpoint

**Frontend (Rust - Leptos):**
- Receives JSON payload with `content: Value`
- Currently displays raw JSON in `<pre>` tag (placeholder)
- **NEW:** Components/markdown.rs provides rendering infrastructure

### Data Structure

```rust
struct MarkdownContent {
    format: String,          // "markdown_ast"
    nodes: Vec<MarkdownNode>
}

struct MarkdownNode {
    kind: String,                           // "heading", "paragraph", "code", etc.
    text: String,                           // Content for leaf nodes
    attrs: BTreeMap<String, String>,        // "level"→"1", "id"→"hello", "language"→"rust"
    children: Vec<MarkdownNode>             // Child nodes for containers
}
```

## Component API

### Main Components

#### 1. `MarkdownRenderer`
Renders complete `MarkdownContent` structure.

```rust
use crate::components::markdown::MarkdownRenderer;

view! {
    <MarkdownRenderer content=markdown_content />
}
```

**Props:**
- `content: MarkdownContent` - Parsed markdown AST

**Output:**
- `<article class="prose prose-sm max-w-none">...</article>`

#### 2. `MarkdownFromValue`
Deserializes JSON value and renders. Use this when receiving from API.

```rust
use crate::components::markdown::MarkdownFromValue;

let content_json = serde_json::json!({
    "format": "markdown_ast",
    "nodes": [...]
});

view! {
    <MarkdownFromValue value=content_json />
}
```

**Props:**
- `value: serde_json::Value` - JSON to deserialize

**Output:**
- Renders markdown on success
- Shows error message on deserialization failure

#### 3. `MarkdownNode` (Internal)
Recursively renders individual nodes. Used by renderer components.

## Troubleshooting

### Issue: "Failed to parse markdown content"

**Cause:** JSON structure doesn't match `MarkdownContent`

**Fix:** Check API response includes `format` and `nodes` fields:
```bash
curl http://localhost:3001/api/v1/page/blogs/first-one | jq '.content'
```

### Issue: Markdown renders but styling looks wrong

**Cause:** Tailwind classes not scanned by build process

**Fix:** Ensure markdown.rs is included in:
```javascript
// tailwind.config.js
content: [
  "src/**/*.rs",      {/* Include all Rust files */}
]
```

### Issue: Images not displaying

**Cause:** `src` attribute contains invalid handle format

**Fix:** Verify backend's `resolve_handle()` is converting handles like `media#image.png` → `/media/image.png`

## Performance Considerations

### Current Implementation

- **Recursive rendering:** O(n) complexity where n = total nodes
- **No memoization:** Re-renders on any parent change
- **Memory efficient:** Nodes stored as struct, not reactive signals

### Optimization (if needed)

For large documents (>1000 nodes):

1. **Virtualization:** Render only visible nodes
2. **Memoization:** Memoize MarkdownNode rendering:
   ```rust
   #[component]
   pub fn MemoizedNode(#[prop(into)] node: MarkdownNode) -> impl IntoView {
       let memoized = move || render_node(node.clone());
       memoized()
   }
   ```
3. **Lazy loading:** Load markdown sections on demand
